Project Overview

To build real-world SIEM and SOC skills, I designed and deployed a complete Splunk-based log aggregation environment using a Windows endpoint and a Kali Linux virtual machine. The goal was to replicate the log collection and forwarding architecture found in enterprise security operations centers — not just read about it, but actually build and operate it.

Every component was manually configured: forwarder deployment, centralized management, firewall log ingestion, syslog infrastructure, and search & analysis. The result is a fully operational pipeline from raw log source to searchable security data.

Components & Configuration

Universal Forwarder — Windows

Installed the Splunk Universal Forwarder on the Windows endpoint and configured it to ship logs to the Kali Linux Splunk receiver. The forwarder was also registered as a Deployment Client, enabling centralized config pushes from the Deployment Server. 

# outputs.conf — Forwarding target
[tcpout]
defaultGroup = splunk-server

[tcpout:splunk-server]
server = 192.168.252.128:9997

# deploymentclient.conf — Deployment Server registration
[target-broker:deploymentServer]
targetUri = 192.168.252.128:8089
UF CONFIG

Windows Event Log Collection

Configured the forwarder to collect all three primary Windows Event Log channels — Application, Security, and System — capturing authentication events, service changes, auditing activity, and more. 

# inputs.conf — Windows Event Log inputs
[WinEventLog://Application]
disabled = 0

[WinEventLog://Security]
disabled = 0

[WinEventLog://System]
disabled = 0
INPUTS.CONF

Windows Firewall Log Monitoring

Enabled packet logging in Windows Defender Firewall (both dropped packets and successful connections), then configured the Universal Forwarder to tail the firewall log file in real time. 

# Windows Firewall — logging enabled for:
#   Log Dropped Packets = Yes
#   Log Successful Connections = Yes

[monitor://C:\Windows\System32\LogFiles\Firewall\pfirewall.log]
disabled = 0
sourcetype = windows_firewall
INPUTS.CONF

Splunk Enterprise — Multi-Role Server (Kali Linux)

A single Splunk Enterprise instance on Kali Linux was configured to fulfill three distinct enterprise roles simultaneously: Search Head for querying and visualization, Heavy Forwarder for receiving forwarded data, and Deployment Server for managing remote forwarder configurations.

rsyslog — Syslog Infrastructure

Installed and configured rsyslog on the Kali Linux server to accept syslog events from any network device over both UDP and TCP on port 514. Remote logs are organized into per-device directories for structured ingestion into Splunk. 

# rsyslog.conf — Remote logging listeners
module(load="imudp")
input(type="imudp" port="514")

module(load="imtcp")
input(type="imtcp" port="514")

# Remote log storage structure:
# /var/log/remote/firewall01/
# /var/log/remote/linux01/
# /var/log/remote/router01/
RSYSLOG.CONF

End-to-End Data Flow

Windows Event Logs → Universal Forwarder → Heavy Forwarder :9997 → Search Head
pfirewall.log → UF Monitor Input → Heavy Forwarder :9997 → Search Head
Linux / Network Devices → rsyslog :514 → Splunk Enterprise → Search Head
